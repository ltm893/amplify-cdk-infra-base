# Changelog

## [1.0.0] - 2026-04-13

Initial build and deployment of the `amplify-cdk-infra-base` CDK stack.

---

### Infrastructure — `lib/setup-stack.ts`

- Created **Public S3 bucket** — publicly readable via bucket policy, CORS configured for GET, HEAD, PUT, DELETE
- Created **Private S3 bucket** — block all public access, versioning enabled, CORS configured for GET, PUT, DELETE, HEAD
- Created **Cognito User Pool** — invite-only, email sign-in, enforced password policy, email account recovery
- Created **Cognito Identity Pool** — federates User Pool logins into temporary AWS credentials for direct S3 access
- Created **Authenticated IAM Role** — grants signed-in users GetObject, PutObject, DeleteObject, ListBucket on both buckets
- All outputs written to CloudFormation: bucket names, User Pool ID, Client ID, Identity Pool ID, IAM role ARN

---

### Scripts

| Script | What it does |
|---|---|
| `scripts/deploy.sh` | Prompts for config, generates `bin/config.ts`, runs `cdk deploy`, auto-generates `amplify_outputs.json` |
| `scripts/check-stack.sh` | Checks CloudFormation stack status and prints all resource outputs |
| `scripts/create-cognito-user.sh` | Invites a new user to the Cognito User Pool via CLI |
| `scripts/destroy.sh` | Runs `cdk destroy` and verifies the stack is gone |
| `scripts/purge-buckets-userpool.sh` | Permanently deletes retained S3 buckets and Cognito User Pool — resolves names from CloudFormation → `amplify_outputs.json` → manual prompt |
| `scripts/setup-venv-test-crud.sh` | Creates Python venv, installs boto3, runs CRUD test suite |
| `scripts/test-crud.py` | Full CRUD test — Create, Read, Update, Delete against both S3 buckets with pass/fail output |

---

### Automation

- `deploy.sh` auto-generates `amplify_outputs.json` after every deploy — no manual copy of resource IDs needed
- `purge-buckets-userpool.sh` resolves resource names automatically so hardcoded values are never needed
- Python venv at `.venv/` is reused across test runs — boto3 only installed once
